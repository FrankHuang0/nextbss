# 網頁功能 Reengineering 教材設計

## 背景與目標

團隊已用知識庫（規格文件＋源碼）搭配 AI，逆向產出網頁功能規格書（Page Spec），以信用查核頁為首個完整案例。本教材讓開發與 BA 同仁學會同一套方法：以源碼為事實，產出業務語言、可追溯、標示驗證狀態的規格書。

## 內容範圍

新增 `page-spec-reengineering.html`，內容依序：

1. 為什麼逆向：傳統規格文件與 Page Spec 對照、事實來源優先序。
2. 製作流程 6 步：定位頁面 → 先規劃後撰寫 → 由 UI 觸發點窮舉規則 → 業務語言＋三重定位 → ✅/⚠ 驗證狀態 → Review 迭代。
3. 規格書結構與規則命名（R／F／D／X）、規則欄位。
4. 去識別化範例：信用查核的業務定位、流程示意、規則分布、一張規則卡。
5. 可複製提示詞 3 則與完成檢查清單。

## 去識別化

公開網站不得出現程式、類別、方法名稱、行號、套件路徑、外部系統代碼、規格文件編號、選單代碼、DB 欄位、具體風險代碼與員工資料；改用「查核主控程式」「外部風險查詢」「帳務系統」「設計規格 §x」等泛稱。以斷言測試列舉禁用詞檢查。

## 網站整合

- `index.html` 新增「工具」類卡片，縮圖沿用知識庫分享圖。
- `assets/nav.js` 新增導覽連結。
- 沿用 `assets/style.css`，不加 CDN、圖片或新依賴；流程以文字示意呈現。
